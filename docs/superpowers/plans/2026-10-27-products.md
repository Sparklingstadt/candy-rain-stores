# 商品の登録・一覧 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** オーナーが商品（画像最大 5 枚）を登録・編集・公開・削除でき、誰でもストアページの商品一覧と商品詳細ページを見られるようにする。

**Architecture:** 第 1 段階と同じく、データベースと Storage はサーバー側だけが触る。`services/productService.ts` が「ログイン中ユーザーの `sub` → 本人のストア → その中の商品」の順に引いて権限を守る。画像は 1 枚ずつ Server Action で送り、既存の `ImageStorage` と `validateImage` を使い回す。

**Tech Stack:** Next.js 16 / React 19 / Auth.js v5 / Prisma 7 + PostgreSQL（Supabase）/ Tailwind CSS 4 / `tsx --test` / Playwright

**Spec:** `docs/superpowers/specs/2026-10-27-products-design.md`

## Global Constraints

- 商品名 1〜80 文字（trim 後）、説明文 2,000 文字まで（空なら null）、価格 1〜9,999,999 の整数、在庫 0〜99,999 の整数。価格・在庫は半角数字のみ（カンマは取り除く）
- 画像は 1 商品 5 枚まで（`MAX_IMAGES_PER_PRODUCT = 5`）、商品は 1 ストア 100 件まで（`MAX_PRODUCTS_PER_STORE = 100`）。追加の直前に親の行を `SELECT ... FOR UPDATE` でロックしてから数える
- 画像のルールは第 1 段階と同じ（`validateImage`、2 MB、PNG/JPEG/WebP）。保存先 `store-images` の `<Store.id>/products/<Product.id>/<randomUUID>.<ext>`
- 1 枚目 = `sortOrder` 最小。追加は「最大 + 1（なければ 0）」、「1 枚目にする」は「最小 − 1」
- 一覧は `createdAt` 降順。価格表示は `¥1,200`
- 新テーブル `Product`・`ProductImage` は RLS 有効（ポリシーなし）
- Storage のファイル削除失敗はログのみ（DB 操作は成功させる）。Storage への保存失敗では DB に行を作らない
- 他人の商品・存在しない商品・別ストアの商品は「見つからない」と同じ扱い（存在を明かさない）
- 文言は日本語。サービスはフォームの値でストアを選ばない（必ず `sub` から）
- 単体テストは `lib/*.test.mts`（`npm test`）、結合テストは `tests/integration/*.test.mts`（`npm run test:integration`、`--conditions=react-server`）

## Review Focus

- URL の商品 ID が UUID の形でない（`/s/shop/products/abc`、`/dashboard/products/abc`）→ Prisma の `@db.Uuid` で例外にせず 404 → Task 3 のテストに含める
- 別のストアの商品 ID を自分のストアの URL に付けて開く（`/s/shop-a/products/<shop-b の商品>`）→ 404 → Task 3 のテストに含める
- 価格に全角数字（`１２００`）・小数（`12.5`）・負数（`-1`）・空文字 → それぞれエラー。`1,200`・`0100` は 1200・100 として受け付ける → Task 1 のテストに含める
- 1 枚目の画像を削除 → 次の画像が自動で 1 枚目（サムネイル）になる → Task 4 のテストに含める
- 2 つのタブから同時に 6 枚目を追加 → 5 枚で止まり、余った方は `limit_reached` で、保存したファイルも消える → Task 4 のテストに含める
