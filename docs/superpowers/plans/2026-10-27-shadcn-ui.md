# shadcn/ui による UI 更新 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 全画面の見た目を shadcn/ui のコンポーネントとテーマで統一する。機能・文言・URL は変えない。

**Architecture:** shadcn/ui（new-york スタイル、base color neutral、CSS 変数）を `components/ui/` に置き、各画面の素の Tailwind 要素を置き換える。ライト／ダークはシステム設定に従う。ストアのテーマカラー（`--store-color`）はストアページの差し色として残す。

**Tech Stack:** Next.js 16、React 19、Tailwind CSS 4、shadcn/ui（class-variance-authority・clsx・tailwind-merge・@radix-ui/react-slot・lucide-react・tw-animate-css）

**Spec:** なし（ユーザーの指示「shadcn.ui で UI を更新して」）。判断は本計画の Global Constraints を基準にする。

## 前提と決定

- この環境からは `ui.shadcn.com`（shadcn CLI のレジストリ）に接続できない。コンポーネントは shadcn/ui の公開ソース（new-york v4、Tailwind 4 版）と同じ内容を `components/ui/*.tsx` に手で置き、`components.json` も用意して、あとから CLI で追加・更新できるようにする。npm パッケージは通常どおり npm から入れる
- フォームは Server Actions と `FormData` で動いているため、選択欄は Radix の Select ではなく shadcn の **Native Select**（`<select>` を装飾したもの）を使う
- ダークモードは `prefers-color-scheme` に従う（切り替えボタンは作らない）
- フォントは追加しない（ビルド時に外部取得が要るため）。システムフォントのまま

## Global Constraints

- 画面の文言・ラベル・ボタン名・URL・フォームの `name`・Server Actions の動作は変えない
- 入力エラーは今と同じく `<p role="alert">` で出す（E2E が `p[role=alert]` を使う）。見た目は `text-destructive text-sm`
- `<label>` と入力欄の対応（`getByLabel` で取れること）を保つ
- ストアページ・商品ページでは `--store-color` を差し色（ヘッダー帯、枠など）として残す
- スマートフォン幅（375px）で横スクロールが出ない
- `npm test`・結合テスト・lint・typecheck・build・E2E 3 本がすべて通る

## Review Focus

- ダークモードで文字や枠が背景に埋もれない（特に `--store-color` の帯の上の文字、alert、無効ボタン）
- ボタンの無効状態（送信中・売り切れ・上限）が見て分かる
- 確認付きの操作（ストア削除・商品削除・注文キャンセル）の確認表示が、破壊的な操作として目立つ（`variant="destructive"`）
- 表（注文一覧）がスマートフォン幅で崩れない（横スクロールは表の中だけに閉じる）
- `Button asChild` で `Link` を包んだときにリンクとして動く
