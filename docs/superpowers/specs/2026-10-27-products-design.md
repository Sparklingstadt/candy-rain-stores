## 本段階のゴール

オーナーが商品を登録し、画像を何枚か付けて公開すると、誰でもストアページで商品一覧を見られる。商品を押すと詳細ページで全部の画像・説明・価格・在庫状況を見られる。

## 決定事項

- 商品の項目：商品名・価格（必須）、説明文・画像・在庫数・公開／非公開
- 画像は 1 商品 **5 枚まで**。1 枚目が一覧のサムネイル
- 公開側はストアページの商品一覧と、商品詳細ページ `/s/<ストアID>/products/<商品ID>`
- 一覧は**新しい順**（`createdAt` 降順）
- 画像は **1 枚ずつ**サーバー経由で送って保存する（Vercel の 1 リクエスト 4.5 MB 上限に収めるため）。ブラウザに Supabase の鍵は渡さない
- 権限の考え方は第 1 段階と同じ。サービスは必ずログイン中ユーザーの `sub` から本人のストアを引き、その中の商品だけを扱う

## データ

### `Product` テーブル

| 列 | 型 | 制約・内容 |
| --- | --- | --- |
| `id` | UUID | 主キー。商品詳細ページの URL に使う |
| `storeId` | UUID | `Store.id` への外部キー。**ON DELETE CASCADE** |
| `name` | text | 商品名 |
| `description` | text, null 可 | 説明文 |
| `price` | integer | 価格（円、税込として表示） |
| `stock` | integer | 在庫数 |
| `isPublished` | boolean | 既定値 `false` |
| `createdAt` / `updatedAt` | timestamp | |

インデックス：`(storeId, createdAt)`。

### `ProductImage` テーブル

| 列 | 型 | 制約・内容 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `productId` | UUID | `Product.id` への外部キー。**ON DELETE CASCADE** |
| `path` | text | Storage 上のパス |
| `sortOrder` | integer | 小さいほど前。最小のものが 1 枚目 |
| `createdAt` | timestamp | |

インデックス：`(productId, sortOrder)`。

### 入力のルール

| 項目 | ルール |
| --- | --- |
| 商品名 | 必須。前後の空白を除いて 1〜80 文字 |
| 説明文 | 任意。2,000 文字まで。空なら null |
| 価格 | 半角数字のみ（カンマは取り除く）。1〜9,999,999 の整数 |
| 在庫数 | 半角数字のみ（カンマは取り除く）。0〜99,999 の整数 |
| 画像 | 第 1 段階と同じ（PNG・JPEG・WebP をファイル先頭バイトで判定、1 枚 2 MB まで）。`validateImage` を使い回す |

### 上限

- 画像：1 商品 5 枚まで
- 商品：1 ストア 100 件まで
- どちらもサービスが追加の直前に数えて判定する。同時に追加されても超えないよう、数える前に親の行（画像なら `Product`、商品なら `Store`）を `SELECT ... FOR UPDATE` でロックする

### 画像の保存

- バケットは第 1 段階と同じ `store-images`
- パス：`<Store.id>/products/<Product.id>/<ランダム>.<拡張子>`
- 追加：新しい画像の `sortOrder` は「今の最大値 + 1」（なければ 0）
- 「1 枚目にする」：その画像の `sortOrder` を「今の最小値 − 1」にする
- 画像の削除・商品の削除のときは Storage のファイルも消す。ファイル削除の失敗はログに残すだけで、データベースの操作は成功させる（第 1 段階と同じ）
- Storage への保存に失敗したら、データベースに行を作らない

### RLS

新しい 2 テーブルにも第 1 段階と同じく RLS を有効にする（ポリシーなし）。Supabase の Data API からは見えない。

## 既存の処理の変更

- `deleteStore`（`services/storeService.ts`）：ストアのロゴ・ヘッダーに加え、そのストアの全商品画像のファイルも Storage から消す。パスはストアの行を消す**前に**集める。データベースの行は外部キーの CASCADE で消える
- `/dashboard`：ストアがあるとき「商品を管理」（`/dashboard/products`）へのリンクを出す
- `/s/<ストアID>`：「商品はまだありません」の場所を商品一覧に置き換える

## 画面と操作

### オーナー用（ログイン必須。ストアがなければ `/dashboard` へ）

| URL | 内容 |
| --- | --- |
| `/dashboard/products` | 商品一覧（サムネイル・商品名・価格・在庫・「公開中」／「非公開」）と「商品を追加」。100 件に達したらボタンを無効にし「商品は 100 件までです」 |
| `/dashboard/products/new` | 商品名・価格・在庫数・説明文を入れて「作成する」。作成すると非公開のまま編集画面へ |
| `/dashboard/products/<商品ID>` | 編集画面。他人の商品・存在しない商品は 404 |

**編集画面**

- 商品名・価格・在庫数・説明文の編集と「保存する」
- 「公開する」／「非公開にする」と「商品ページを見る」
- 画像：今の画像を順に並べ、それぞれに「1 枚目にする」（1 枚目以外）と「削除」。「画像を追加」でファイルを 1 枚選ぶとその場で送信・保存する。2 MB を超えるファイルは送る前に「画像は 2MB 以下にしてください」。5 枚に達したら追加欄を無効にし「画像は 5 枚までです」
- 商品の削除：「商品を削除」を押すと「本当に削除しますか？」と確定ボタンが出て、確定すると削除して商品一覧へ戻る

### お客さん向け

**ストアページ `/s/<ストアID>`**

- 公開中の商品を新しい順にカードで並べる。カードは 1 枚目の画像（なければテーマカラーの枠）・商品名・価格（`¥1,200`）・在庫 0 なら「売り切れ」。カードを押すと商品詳細へ
- 商品がなければ「商品はまだありません」
- オーナー本人には非公開の商品も「非公開」の印を付けて並べる

**商品詳細ページ `/s/<ストアID>/products/<商品ID>`**

- 大きな画像 1 枚と、その下に全画像の小さな一覧。小さい画像を押すと大きい画像が切り替わる（画像がなければテーマカラーの枠）
- 商品名・価格・在庫状況（「在庫 3 点」／「売り切れ」）・説明文（改行を保持、HTML として解釈しない）・「ストアに戻る」
- ページタイトルは「<商品名> | <ストア名>」

| 状態 | 表示 |
| --- | --- |
| ストアと商品が両方公開中 | 誰でも表示 |
| どちらかが非公開・オーナー本人 | 「非公開です（あなたにだけ表示されています）」の帯を付けて表示 |
| どちらかが非公開・それ以外 | 404 |
| 存在しない商品、または URL のストアに属さない商品 | 404 |

非公開の商品名がタイトル（`<title>`）からオーナー以外に漏れないよう、`generateMetadata` も同じ見え方の判定を使う。

## エラーの扱い

- 入力の誤りは項目ごとに日本語で表示し、入力内容を保持する
- 画像の形式・サイズ違反、画像 5 枚・商品 100 件の上限は、それぞれメッセージを表示する
- 2 つのタブから同時に 6 枚目を追加しても 5 枚を超えない（ロックで保証）
- 他人の商品の ID を指定した操作は「見つからない」として扱う（存在を明かさない）
- 想定外のエラーは第 1 段階の `app/dashboard/error.tsx` が受ける
