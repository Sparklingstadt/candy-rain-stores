# ストア作成と公開ページ 設計

- 日付：2026-10-27
- 対象：candy-rain-stores

## 背景と全体の進め方

Candy Rain Stores は、Candy Rain ID を持つユーザーが自由にストアを運営できるサービスである。最終的にはお客さんが商品をカートに入れて購入できるところまでを目指し、次の 4 段階に分けて作る。各段階は「設計 → 実装 → マージ」まで終えてから次へ進む。

| # | 内容 | 状態 |
| --- | --- | --- |
| 1 | ストア作成と公開ページ（**本設計**） | |
| 2 | 商品の登録・一覧 | 未着手 |
| 3 | カートと注文（決済なし。代金のやり取りはサービスの外で行う） | 未着手 |
| 4 | 決済 | 当面は作らない |

## 本段階のゴール

ログインしたユーザーがストアを作り、公開にすると、ログインしていない人も `/s/<ストアID>` でストアページ（ストア名・説明文・ロゴ・ヘッダー画像・テーマカラー）を見られる。あわせて、オーナーはストアの編集・公開／非公開の切り替え・削除と、ログアウトができる。

## 決定事項

- 1 人のユーザーが持てるストアは **1 つまで**
- 公開ページの URL は `/s/<ストアID>`
- データベースは **Supabase**（PostgreSQL）。画像は **Supabase Storage**
- データベース・Storage へのアクセスは **Next.js のサーバー側だけ**で行う。ブラウザには Supabase の鍵を渡さず、Supabase Auth と RLS は使わない。権限の判定（オーナー本人か、公開中か）はサーバーのコードで行う
- ORM は candy-rain-store と同じ **Prisma**
- 見た目は candy-rain-store と同じ **Tailwind CSS** で最低限整える

## データ

### `Store` テーブル

| 列 | 型 | 制約・内容 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `ownerSub` | text | オーナーの Candy Rain ID の `sub`。**unique**（1 人 1 ストアをデータベースでも保証する） |
| `slug` | text | ストア ID。**unique**。作成後は変更不可 |
| `name` | text | ストア名 |
| `description` | text, null 可 | 説明文 |
| `logoPath` | text, null 可 | Storage 上のロゴ画像のパス |
| `headerPath` | text, null 可 | Storage 上のヘッダー画像のパス |
| `themeColor` | text | `#rrggbb`。既定値 `#e85d8f` |
| `isPublished` | boolean | 既定値 `false` |
| `createdAt` / `updatedAt` | timestamp | |

### 入力のルール

| 項目 | ルール |
| --- | --- |
| ストア ID | 英小文字・数字・ハイフンのみ、3〜30 文字、先頭と末尾はハイフン不可（`^[a-z0-9](?:[a-z0-9-]{1,28}[a-z0-9])$`）。前後の空白は取り除き、大文字は小文字にそろえる |
| ストア名 | 必須。前後の空白を取り除いて 1〜50 文字 |
| 説明文 | 任意。500 文字まで。空なら null |
| テーマカラー | `#rrggbb`（16 進 6 桁）。小文字にそろえる |
| 画像 | PNG・JPEG・WebP のみ、1 枚 2 MB まで。形式はファイル先頭のバイト列で判定し、拡張子や Content-Type だけを信用しない |

### 画像の保存

- 公開バケット `store-images` に `<Store.id>/logo-<ランダム>.<拡張子>`・`<Store.id>/header-<ランダム>.<拡張子>` で保存する
- 差し替え・削除のときは古いファイルを Storage から消す
- 非公開ストアの画像も URL を知っていれば見える。ファイル名にランダムな文字列を含めて推測されにくくする（許容する）
- 画像 2 枚と他の項目を 1 回で送るため、Server Actions の `bodySizeLimit` を 5 MB にする

## 画面と操作

### `/`

- 未ログイン：「Candy Rain ID でログイン」
- ログイン済み：`/dashboard` へリダイレクト

### `/dashboard`（ログイン必須。未ログインなら `/` へ）

ヘッダーに「ログアウト」ボタンを置く。

**ストアがないとき：作成フォーム**

- ストア名・ストア ID・説明文・テーマカラー（カラーピッカー）・ロゴ・ヘッダー画像
- ストア ID の下に「URL: …/s/<入力中の ID>」と「作成後は変更できません」を表示
- 作成すると非公開のまま編集フォームへ

**ストアがあるとき：編集フォーム**

- ストア ID は表示のみ。ほかの項目は変更できる。画像は差し替えと削除ができる
- 「公開する」／「非公開にする」ボタンと、ストアページへのリンク
- 一番下に「ストアを削除」。ストア ID を入力したときだけ削除できる。削除するとデータベースの行と Storage の画像を消し、作成フォームに戻る。削除したストア ID はすぐ再利用できる

### `/s/<ストアID>`（ログイン不要）

| 状態 | 表示 |
| --- | --- |
| 公開中 | 誰でも表示 |
| 非公開・オーナー本人 | 「非公開です（あなたにだけ表示されています）」の帯を付けて表示 |
| 非公開・それ以外 | 404 |
| 存在しない | 404 |

ヘッダー画像・ロゴ・ストア名・説明文をテーマカラーで表示する。商品一覧の場所は第 2 段階まで空けておく。

### ログアウト

stores のセッションを消したあと、Candy Rain ID の `/logout?client_id=candy-rain-stores&post_logout_redirect_uri=<stores の origin>/` へ送り、ID サーバー側のログイン状態も消して `/` に戻る。ログイン状態はクライアント間で共有されているため、candy-rain-store からもログアウトされる。

## エラーの扱い

- 入力の誤りは項目ごとに日本語で表示し、入力内容を保持する（ファイル入力は再選択が必要）
- ストア ID の重複：「このストア ID はすでに使われています」
- すでにストアを持つユーザーの作成（2 つのタブから同時に作成など）：`ownerSub` の unique 制約で弾き、編集フォームへリダイレクト
- 画像の形式・サイズ違反：その項目にメッセージ
- 削除時のストア ID 入力が一致しない：削除しない
- Storage への保存に失敗：データベースは更新しない。保存済みの新しい画像は消す
- Storage からの削除に失敗（古い画像の削除）：データベースの更新は成功させ、ログに残す（ゴミが残るだけで表示には影響しない）
- 他人のストアは操作できない：Server Actions はフォームの値でストアを指定せず、ログイン中ユーザーの `sub` からストアを引く

## テスト

| 種類 | 内容 |
| --- | --- |
| 単体 | `lib/storeValidation.ts`（ストア ID・名前・説明文・色・画像の形式とサイズ） |
| 結合 | ローカル PostgreSQL に対して `services/storeService.ts` を実行：作成、ID 重複、1 人 1 ストア、他人のストアを更新・削除できない、公開／非公開での取得、削除後の ID 再利用 |
| E2E | ローカルの Candy Rain ID と Playwright：ログイン → 作成 → 非公開中はログアウト状態で 404 → 公開 → ログアウト状態で表示 → 削除 → ログアウト |
| CI | GitHub Actions で lint・型チェック・単体テスト・結合テスト（PostgreSQL サービスコンテナ） |

Storage は結合テスト・E2E ではテスト用の差し替え（ローカルのメモリ実装）を使い、本物の Supabase には書き込まない。

## 作らないもの（本段階）

- ストア ID の変更
- 商品・カート・注文・決済（第 2 段階以降）
- 画像のリサイズ・トリミング
