## 本段階のゴール

ログインしたお客さんが、別々のストアの商品を 1 つのカートに入れ、住所と電話番号を入力して注文を確定すると、ストアごとに注文が作られて在庫が減る。各オーナーは自分のストアの注文だけを見て「支払確認」「発送済み」と進められ、お客さんは「注文履歴」で状態とストアの支払い方法の案内を確認できる。代金のやり取りはサービスの外で行う。

## 決定事項

- 購入には Candy Rain ID でのログインが必須
- カートはサービス全体で 1 つ（ユーザーごとにデータベースに保存）。注文確定時にストアごとの注文に分ける
- 注文時の入力：お届け先（郵便番号・都道府県・住所）と電話番号。名前とメールアドレスは Candy Rain ID のものを記録する
- 注文の状態：受付 → 支払確認 → 発送済み、とキャンセル
- 支払い方法の案内はストアごとにオーナーが書く。送料の欄は作らない
- 注文確定時に在庫を減らし、キャンセルで戻す（商品が削除済みなら戻さない）
- 注文の商品名・単価・ストア名・支払い方法の案内は、注文時点のものを記録する
- オーナーは自分のストアの商品を買えない
- 数量は 1 商品 1〜10 個、カートは 30 種類まで
- 注文確定は**全部成功か、何も起きないか**のどちらか

## データ

### `Store` に追加

| 列 | 型 | 内容 |
| --- | --- | --- |
| `paymentInstructions` | text, null 可 | お支払い方法の案内（1,000 文字まで）。空なら表示時に「お支払い方法はストアからの連絡をお待ちください」 |

### `CartItem`

| 列 | 型 | 制約・内容 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `buyerSub` | text | 購入者の Candy Rain ID の `sub` |

| `quantity` | integer | 1〜10 |
| `createdAt` / `updatedAt` | timestamp | |

- `(buyerSub, productId)` は unique。同じ商品を再び入れると数量を足す（上限 10 で止める）
- インデックス：`(buyerSub, createdAt)`

### `Order`（ストアごとに 1 件）

| 列 | 型 | 制約・内容 |
| --- | --- | --- |
| `id` | UUID | 主キー。画面では先頭 8 文字を大文字にして「注文番号」として表示 |

| `buyerSub` | text | |

| `status` | enum `OrderStatus` | `RECEIVED`（受付）・`PAID`（支払確認）・`SHIPPED`（発送済み）・`CANCELED`（キャンセル） |

| `createdAt` / `updatedAt` | timestamp | |

インデックス：`(storeId, status, createdAt)`・`(buyerSub, createdAt)`。

| 列 | 型 | 制約・内容 |
| --- | --- | --- |

| `orderId` | UUID | `Order.id` への外部キー。**ON DELETE CASCADE** |
| `productId` | UUID, null 可 | `Product.id` への外部キー。**ON DELETE SET NULL** |
| `productName` | text | 注文時点の商品名 |
| `unitPrice` | integer | 注文時点の単価 |
| `quantity` | integer | |

新しいテーブルはすべて RLS を有効にする（ポリシーなし）。

### 入力のルール

| 項目 | ルール |
| --- | --- |
| 郵便番号 | 前後の空白を除き、半角数字 7 桁（3 桁目の後のハイフンは任意）。`123-4567` の形で保存 |
| 都道府県 | 47 都道府県の名前のどれか |
| 住所 | 前後の空白を除いて 1〜200 文字 |
| 電話番号 | 前後の空白を除き、半角数字とハイフンのみ。ハイフンを除いた数字が 10〜11 桁。入力どおり保存 |
| 支払い方法の案内 | 1,000 文字まで。空なら null |
| 数量 | 1〜10 の整数 |

## 注文の確定（`placeOrder`）

1 つのトランザクションで次を行う。

1. 購入者のカートを読み、空なら `empty_cart`
2. カートの商品の行を **ID 順**に `SELECT ... FOR UPDATE` でロックする（同時注文で在庫を数え間違えず、デッドロックも起こさない）
3. 各商品を確かめる。問題があれば理由を集める
   - 商品が非公開、またはストアが非公開 → `unavailable`
   - 在庫 < 数量 → `insufficient_stock`（残り在庫も返す）
   - 自分のストアの商品 → `own_store`
4. **問題が 1 つでもあれば、何も変更せず**問題の一覧を返す
5. 問題がなければ、在庫を減らし、ストアごとに `Order` と `OrderItem` を作り、注文した `CartItem` を消す。作った注文の ID を返す

## 状態の変更

| 誰が | できること |
| --- | --- |
| オーナー | `RECEIVED` → `PAID` → `SHIPPED`。`RECEIVED`・`PAID` → `CANCELED` |
| お客さん | `RECEIVED` → `CANCELED` のみ |

- 更新は「`id` と所有者と**今の状態**が一致するときだけ」行う（`updateMany` の条件に今の状態を入れる）。0 件なら `conflict` を返し、画面に「注文の状態が変わりました。画面を更新してください」
- `CANCELED` にするときは同じトランザクションで在庫を戻す（`productId` が残っている明細だけ）

## 既存の処理の変更

- `deleteStore`：そのストアに `RECEIVED`・`PAID` の注文があれば削除せず `has_open_orders` を返し、「対応中の注文があるため削除できません」と表示する。なければ削除し、過去の注文は `storeId` が null になって残る
- 商品の削除：変更なし（カートからは CASCADE で消え、明細は `productId` が null になって残る）
- `auth.ts`：セッションに Candy Rain ID の名前とメールアドレスを載せる（`lib/session.ts` に `getBuyer()` を足す）
- ストアの編集フォームに「お支払い方法の案内」を足す

## 画面と操作

### 共通ヘッダー（ストアページ・商品詳細・カート・注文手続き・注文履歴）

「Candy Rain Stores」（`/`）・「カート（N）」（N は数量の合計）・「注文履歴」・ログイン中なら「ログアウト」、未ログインなら「ログイン」。

### 商品詳細ページ

数量（1〜10 の選択）と「カートに入れる」。追加したら「カートに入れました」とカートへのリンクを表示する。

| 状況 | 表示 |
| --- | --- |
| 未ログイン | 「ログインしてカートに入れる」。ログイン後はその商品ページに戻る |
| 在庫 0 | 「売り切れ」（無効） |
| 自分のストアの商品 | 「自分のストアの商品は購入できません」 |
| 非公開のプレビュー（オーナー） | ボタンなし |

### `/cart`（ログイン必須）

- 商品をストアごとにまとめて表示。各商品は画像・商品名（商品ページへのリンク）・単価・数量の選択（変えるとすぐ保存）・「削除」・小計。ストアごとの小計と合計
- 購入できない商品には理由：「現在購入できません」・「在庫が足りません（残り N 点）」・「自分のストアの商品は購入できません」。売り切れは「在庫が足りません（残り 0 点）」
- 購入できない商品があれば「注文手続きへ」を無効にし「購入できない商品があります。数量を変えるか削除してください」
- 空なら「カートは空です」
- 30 種類に達していたら商品ページで「カートに入れられるのは 30 種類までです」

### `/checkout`（ログイン必須。カートが空・購入できない商品ありなら `/cart` へ）

- 郵便番号・都道府県（選択）・住所・電話番号。前回の注文の値を初期値に入れる
- ストアごとの注文内容と合計の確認、「注文を確定する」
- 確定時に問題があれば `/cart` に戻して「在庫や公開状態が変わったため、注文を確定できませんでした」と表示

### `/orders`（ログイン必須）

- 確定直後（`?placed=1`）は「ご注文を受け付けました。ストアごとに注文が作られています。お支払い方法は各注文の案内をご確認ください」
- 新しい順：注文番号・ストア名・注文日時（日本時間）・合計・状態

### `/orders/<注文ID>`（ログイン必須。自分の注文以外は 404）

- 注文番号・ストア名（ストアが残っていればストアページへのリンク）・日時・状態・明細・合計・お届け先・電話番号・お支払い方法の案内
- `RECEIVED` のとき「注文をキャンセル」→「本当にキャンセルしますか？」と「キャンセルする」「やめる」

### `/dashboard` に追加

ストアがあるとき「注文を管理（受付 N 件）」→ `/dashboard/orders`。ストアの編集フォームに「お支払い方法の案内」。

### `/dashboard/orders`（ログイン必須。ストアがなければ `/dashboard` へ）

- 状態で絞り込むタブ：すべて・受付・支払確認・発送済み・キャンセル（`?status=`）
- 新しい順に最新 100 件：注文番号・日時・購入者名・合計・状態

### `/dashboard/orders/<注文ID>`（自分のストアの注文以外は 404）

- 購入者の名前・メールアドレス・電話番号・お届け先、明細、合計、状態
- 状態に応じたボタン：受付「支払いを確認した」「キャンセルする」、支払確認「発送した」「キャンセルする」、発送済み・キャンセルはなし。キャンセルは確認付き

## エラーの扱い

- 入力の誤りは項目ごとに日本語で表示し、入力内容を保持する
- 状態変更の競合は「注文の状態が変わりました。画面を更新してください」
- 他人の注文・UUID でない ID は 404（存在を明かさない）
- 対応中の注文があるストアの削除は「対応中の注文があるため削除できません」
- 想定外のエラーは日本語のエラー画面（`app/dashboard/error.tsx` と同様のものをお客さんの画面にも置く）
